# Правила базы знаний

**Общие правила — соседний скилл skill-skill, `knowledge/00_ПРАВИЛА.md`**:
что хранить, структура 10_/20_/30_/40_, шапка записи и статусы, добавление,
обновление и удаление, `SKILL.md` и установка, проверка целостности, язык.
Работа с репозиторием — там же, 40-02; здесь — 40-02 с особенностями
набора.

## Особенности набора

* **Что хранить:** поведение Visual State (Coder, HCoder, Verificator,
  Validator, Designer, Control Center, State Machine API), расходящееся с
  документацией IAR или интуицией; командные строки, ключи, коды возврата,
  подобранные опытом.
* **Не хранить:** то, что есть в документации IAR (`<установка>\doc\
  UserGuide.chm`, `doc\StateMachineAPI\html`) — только ссылка и
  расхождение с реальностью; общие сведения о Python, C и автоматах;
  **ничего о проектируемом изделии** — примеры только на `examples\`
  поставки (CDPlayer, AVSystem) или отвлечённых моделях («кнопка»,
  «лампа»), [40-02](40_СРЕДА/40-02_работа_с_репозиторием.md).
* **Разделы:** `10_API` — формат модели, Coder, Verificator, Control
  Center, State Machine API, вызовы `vskit`; `20_ПРИЁМЫ`; `30_ГРАБЛИ`;
  `40_СРЕДА` — установка, версии, лицензия, репозиторий.
* **`applies_to` обязано называть версию Visual State.** В записях
  `30_ГРАБЛИ` раздел «Как неправильно» обязателен.
* Знание о коде дублируется одной-двумя фразами в docstring функции
  `vskit/` со ссылкой на запись.
* **Язык:** термины — автомат, состояние, событие, действие, переход,
  условие (guard), регион; имена ключей, функций и элементов XML — как есть;
  числа с единицами — «0.1 с», «30 с». Код в примерах — рабочий целиком.
* Проверка набора: `python tools/check_docs.py --project "<папка
  проекта>"` (обёртка общей проверки; особое — `tools/kit_local.py`: имена
  из моделей проекта) и `tests\` (README).

## Как пользоваться базой

От дешёвого к дорогому: `SKILL.md` -> `INDEX.md` -> файл базы -> docstring
`vskit/` -> документация IAR (`doc\UserGuide.chm`; для поиска — `hh.exe
-decompile <папка> UserGuide.chm` и поиск по .htm;
`doc\StateMachineAPI\html\index.html`; ключи — `vk.options_help("hcoder")`)
-> эксперимент на копии модели, результат записывается. **Опыт важнее
документации:** при расхождении верить базе и перепроверять только при
смене версии.

## Версия: база собрана на Visual State 9.1.1.3863

Всё, что записано до 12.10.2026, получено на **IAR Visual State 9.1.1.3863**
(`vk.version()`), Windows 10 64-bit, Python 3.13, arm-none-eabi-gcc 10.3.1,
lxml 6.1.3. **На другой версии** запись `проверено` читается как `не
проверено`, пока не подтверждена. Самое вероятное расхождение:

* номер формата файлов (`format="11"` в .vsp/.vsr) и схема XML — Designer
  новой версии пишет новый формат, `vskit.design` пишет 11;
* ключи Coder/HCoder (`vk.options_help()`);
* поведение Control Center (перевод строки, ответы на ошибки).

Прогнать `tests\` после обновления Visual State; упала проверка — найти
запись, перепроверить, обновить: прежнее утверждение уходит в раздел
«История» записи с версией.
