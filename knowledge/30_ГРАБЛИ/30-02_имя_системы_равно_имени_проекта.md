# Имя системы = имя проекта

## Что происходит

По умолчанию файлы проекта — `$(PRJNAME).c/.h`, файлы системы —
`$(SYSNAME).c/.h`, всё в одну папку `-path`. У примера CDPlayer проект и
система оба `CDPlayer`:

```
Coder completed - 0 error(s), 0 warning(s)      код 0
out\  CDPlayer.c  CDPlayer.h  CDPlayer.ipcf  coder.xsl  vscoder.cre
```

Файлов 2 вместо 4, `CDPlayer.h` содержит `#include "CDPlayer.h"` (сам
себя), типов проекта нет — код не соберётся, а кодер доволен.

## Как правильно

* В новой модели — разные имена: `Project("LampProject")`,
  `add_system("LampSys", ...)`; `add_system` с именем проекта отказывает.
* Для чужой модели — переименовать файлы проекта ключами:
  `-projectheaderCDPlayer_prj.h -projectsourceCDPlayer_prj.c`.
  `vk.generate()` делает это сам и пишет примечание в `r.notes`.

## Как неправильно

Смотреть только на код возврата и «0 error(s)». Проверять — что `.h`
разных имён ровно столько, сколько систем плюс один, и `compile_check`.

## Чем подтверждено

12.10.2026: ручной запуск HCoder и Coder на копии CDPlayer — по 2 файла
.c/.h; с ключами — 4 файла, `compile_check` OK; `tests/test_coder.py`
проверяет различие имён заголовков.
