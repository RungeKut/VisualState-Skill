# Проверка модели

## Кто что ловит (всё — случаи из этой сессии)

| Путь | Поймал | Пропустил бы |
|---|---|---|
| XML-разбор против State Machine API (`smapi.inventory`) | разбор format 1 видел 0 вершин — у format 1 тег `vertex`, а не `stateVertex` | — |
| XML-схема (`schema_check`) | `exitReactions` не на своём месте | Verificator не запускался бы вовсе |
| `Machine.check()` в `save()` | несуществующие событие и действие | Coder сказал бы только «без триггера» ([30-04](../30_ГРАБЛИ/30-04_неизвестное_имя_события_теряет_триггер.md)) |
| Verificator | выход за домен (`level = lvl` без ограничения `lvl`), конфликт внутреннего и внешнего перехода | Coder и gcc — 0 ошибок |
| HCoder | ветка выбора без `triggerLessTransition` | Verificator и Validator — без замечаний |
| `compile_check` | затёртые файлы при совпадении имён ([30-02](../30_ГРАБЛИ/30-02_имя_системы_равно_имени_проекта.md)), нехватку символов | кодер с кодом 0 |
| сценарий в Validator | поведение (порядок exit/transition/entry, значения) | все статические проверки |
| `designer_check(save=True)` | что Designer принимает модель без вопросов и без потерь | — |

## Как правильно

```python
rep = vk.full_check(vsp, out_dir)        # схема, API, Verificator, кодер, gcc
print(rep); rep.check()
with vk.Simulator(vsp) as s: ...         # сценарий событий -> ожидания
vk.designer_check(vsp, save=True)        # раз в цикл правок модели
```

Ожидания сценария брать из требований к поведению, а не из первого
прогона Validator.

## Как неправильно

Одна «зелёная» проверка — «модель готова». Код возврата любой программы
Visual State — не доказательство ([30-05](../30_ГРАБЛИ/30-05_verificator_код_возврата.md)).
