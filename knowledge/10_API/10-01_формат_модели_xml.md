# Формат модели

## Файлы проекта

| Файл | Что это | Нужен Coder |
|---|---|---|
| `.vsp` | проект: системы, их файлы автоматов, элементы уровня проекта, настройки печати | да |
| `.vsr` | автомат верхнего уровня (topstate): элементы, регионы, состояния, переходы | да |
| `.vnw` | рабочая область Navigator: активная система, выбор Coder/HCoder (`ActiveCoder`) | нет |
| `.vtg` | ключи Coder из Navigator (`CODER_CMDLINE`, разделитель `#`) | только с `--l` |
| `.vws` | рабочая область Validator (INI) | нет; Validator без неё задаёт вопрос ([30-06](../30_ГРАБЛИ/30-06_control_center_перевод_строки_и_диалоги.md)) |
| `.vdi`, `.stereotypes`, `*.bk1..bk3` | вид окна Designer, стереотипы, резервные копии Designer | нет |

Всё — UTF-8 XML (кроме `.vws`), пространство имён
`http://www.iar.com/visualSTATE/2011/Modelfile` (у format 1 его нет).

## Формат 11 (так сохраняет Designer 9.1)

`.vsr` — корень `modelFile` сам является автоматом верхнего уровня:

```
modelFile format="11" guid name
  expl, alias, position, stateProperties
  elements
    actionsFolder name="root"   actionFunction (returnType, arguments)
    constantsFolder             constant (type, value)
    eventsFolder                event (arguments)
    eventGroupsFolder
    externVariablesFolder       externVariable (type, value)
    internVariablesFolder       internVariable (type, value, lowerDomain, upperDomain)
    signalsFolder
  regions        regionBlock guid=…          ссылка на регион верхнего уровня
  regionBlocks   region guid name …  vertices/vertexBlock guid=…
  vertexBlocks   stateVertex | pseudoStateVertex kind=… | finalStateVertex
```

Вершины — плоским списком; вложенность — через `regions/regionBlock` у
`stateVertex`. Ссылки: `externalTransition source/target` — GUID вершин,
`trigger guid` — GUID события, `positiveState` — GUID состояния. **Вызов
действия — по имени**: `actionCall actionFunction="LampSet"`, аргументы —
`actionCallArgument token="level"`. Условие и присваивание — текст:
`<guard>lvl > 1</guard>`, `<assignment>level = lvl</assignment>`.

Порядок детей `stateVertex` задан схемой: expl, alias, position,
stateProperties, entryReactions, internalTransitions, exitReactions,
externalTransitions, regions, tags ([30-08](../30_ГРАБЛИ/30-08_порядок_элементов_по_схеме.md)).

Координаты (`position`, `routePoint`) — в системе региона, где лежит
вершина; точки маршрута перехода — относительно рамки источника и цели.
Coder их не читает; Designer открывает модель с грубой сеткой от
`vskit.design` без вопросов.

## Форматы 1, 6, 8 (примеры поставки)

`.vsr` — корень `modelFile`, внутри `topstate` и полностью вложенное
дерево: `regions/region/vertices/stateVertex/regions/...`. Ссылки — путём
из имён с регионами: `source="Top.Region.CDPlayerOn.rStatus.Playing"`,
`trigger name="evPlayKey"`. В format 1 вершина — `vertex
kind="normalState"`, а файл автомата в .vsp — `<file name="X.vsr"/>`.
Visual State 9.1 читает все эти форматы; Designer при сохранении
переводит в 11.

## Как читать и писать скриптом

```python
import vskit as vk
p = vk.load(r"C:\копия\Project.vsp")        # любой формат 1..11
print(p)                                     # дерево, переходы текстом
p.to_dict()                                  # для JSON и сравнений

m = vk.Machine("Lamp")                       # описание -> format 11
...
vsp = vk.Project("LampProject").add_system("LampSys", m).save(r"C:\w")

d = vk.from_project(vk.load(vsp))            # правка: GUID сохраняются,
d.systems[0][2][0].state("Off2")             # раскладка строится заново
d.save(r"C:\w2")
```

Подробности описания — [20-02](../20_ПРИЁМЫ/20-02_автомат_текстом_на_python.md).
Схема для проверки — [10-05](10-05_state_machine_api_и_схема.md).

## Чем подтверждено

12.10.2026: `tests/test_model.py` — XML-разбор всех `examples\**\*.vsp`
совпал с State Machine API по числу вершин, внешних и внутренних
переходов; CDPlayer format 6 и он же после `VSMProjectSave` (format 11)
дали одинаковый `to_dict()`. `tests/test_design.py` — модель с вложенными
и ортогональными регионами, внутренним переходом, аргументами событий и
`[in State]` прошла схему, Coder, HCoder, gcc, Verificator без замечаний;
Designer открыл её через Control Center и сохранил — разбор сохранённого
совпал с исходным.

Не проверено: подмашины (`submachineStateVertex`), точки входа/выхода,
fork/join, группы событий, сигналы и элементы уровня проекта в записи
(`vskit.design` их не пишет; `vskit.model` читает элементы проекта).
